Você deve definir e/ou gerar estrutura de testes para:

2. Testes de Integração:
   - Fluxos completos dentro da tela (filtros + tabela + gráfico).
   - Interação “tela principal ↔ popup”:
     • Abrir popup,
     • Carregar dados,
     • Confirmar/cancelar,
     • Atualizar tela principal.

3. Testes E2E (Cypress/Playwright ou similar):
   - Caminhos críticos:
     • Login (se existir) → Navegar até dashboard → Ver dados carregados.
     • Dashboard → clicar em transação → abrir popup → ver detalhes → fechar.
     • Tela de Transações → aplicar filtros → abrir detalhes → voltar.
     • Calibragem Manual → alterar parâmetros → abrir popup de confirmação → aplicar → verificar que dashboard/monitoramento refletem mudanças.
     • Hard Rules → criar regra → confirmar no popup → simular efeito em transações (se possível).
     • VIP/HOT → adicionar entrada via popup → salvar → verificar contadores/métricas.
     • Trilhas de Auditoria → executar ações → verificar se aparecem na lista/log.

O objetivo aqui não é apenas “ter teste”, mas GARANTIR que fluxos reais do usuário estão protegidos contra regressões.
